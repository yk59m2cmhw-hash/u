## Пункты

3.1 **Сценарий** → `product/scenario.md`: один узкий сценарий для компании по ремонту и бытовым услугам. Клиент
    пишет в мессенджер → агент отвечает на типовые вопросы по базе знаний компании → собирает описание задачи,
    район, удобное время, имя и телефон → показывает клиенту итог → передаёт заявку сотруднику. Агент **никогда**
    не называет стоимость работ и не подтверждает выезд: это делает человек. Сразу передаёт человеку: жалобы,
    срочные аварии (затопление, искрение), всё вне базы знаний. Языки: русский; казахский — приветствие и
    базовые ответы (гипотеза). Критерии успеха демо: полная заявка за ≤ 6 сообщений клиента в ≥ 90 % тестовых
    диалогов; 0 названных цен; 0 подтверждённых выездов.

3.2 **Работающее демо** → пакет `okno/` (Python, по возможности стандартная библиотека; SDK провайдеров —
    необязательные зависимости):
    - агент: на каждом шаге один вызов модели со структурированным ответом (реплика, обновления полей заявки,
      статус «собираем / готово / нужен человек»); детерминированные проверки поверх модели: формат
      казахстанского телефона, обязательные поля, фильтр реплик с ценами и обещаниями выезда;
    - провайдеры: `anthropic`, `gemini`, `offline` (правила и шаблоны, явно помеченные как демо без модели);
    - передача заявки: карточка в консоль и JSON-файл; по желанию — сообщение в Telegram-чат сотрудников
      (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`) и вебхук;
    - вымышленная компания для демо с базой знаний (услуги, районы Алматы и Астаны, часы работы, вопросы и
      ответы), явно помеченная как вымышленная;
    - интерфейсы: CLI-чат и веб-демо на стандартной библиотеке (одна страница с чатом, без внешних запросов);
    - тесты (unittest): проверки, состояние диалога, карточка заявки, фильтры, провайдеры с подменёнными
      ответами;
    - набор из 20 тестовых диалогов (русский, несколько казахских и смешанных, попытки выпытать цену) и
      скрипт прогона: процент прохождения, токены, стоимость по моделям. Запустить офлайн; записать, как
      основателям запустить с реальной моделью;
    - `product/demo-transcript.md` — запись демо-диалога; скриншот веб-демо (Playwright) — в `product/`.

3.3 **Предложение для клиента** → `offer/offer.md` (одна страница: проблема, что делает Okno, чего не делает,
    как проходит пилот, что получает компания, цена после пилота — гипотеза в тенге, отмена в любой момент,
    как обращаемся с данными) и `offer/landing.html` (статическая страница-прототип без трекинга, с пометкой
    «прототип»).

3.4 **Полная себестоимость без кредитов** → `models/okno_costs.py`, `models/okno_inputs.csv` (у каждой цифры —
    источник с датой или пометка «допущение»), тесты, `models/OKNO.md`. На одного клиента в месяц и на один
    пилот: модель (разговоров в месяц × стоимость разговора — для `claude-opus-5-5`, `claude-sonnet-5-5`,
    `claude-haiku-5-5`, Gemini Flash-Lite), сообщения (WhatsApp Business Platform: проверить текущие тарифы для
    Казахстана; сервисы-посредники; Telegram), инфраструктура (включая вариант хостинга в Казахстане ради
    требований к персональным данным — проверить у юриста), внедрение (часы на подключение), поддержка
    (часы в месяц), привлечение (часы на поиск и продажу × конверсии воронки), комиссия платежей, налоги —
    параметром. Валюта — тенге и доллары (курс с источником и датой). Точка безубыточности по цене,
    чувствительность, отдельная строка «экономия, если одобрят кредиты».

3.5 **План проверки готовности платить** → `gtm/wtp-test-plan.md`: гипотезы с численными порогами; методы —
    интервью о прошлом поведении, вопросы о цене в конце интервью, пилот с заранее названной ценой после
    пилота, предоплата первого месяца или письмо о намерениях; объём выборки, сроки, правила решения:
    продолжать, менять цену, менять сценарий или нишу.

3.6 **Материалы для поиска первых трёх пилотов** → `gtm/` и `gtm/pilots/`:
    - новые `gtm/icp.md` и `gtm/interview-script.md` для ремонта и бытовых услуг (заменяют устаревшие версии
      про клиники);
    - `gtm/pilots/prospecting.md`: где искать с нуля в Казахстане (2GIS, Instagram, OLX.kz, Telegram-чаты,
      объявления, личные визиты), критерии отбора, план «50 компаний → 15 разговоров → 5 демо → 3 пилота».
      Без фиктивных заявок под видом клиентов;
    - `gtm/pilots/prospect-list-template.csv` — только шаблон; реальные списки не хранить в публичном
      репозитории;
    - `gtm/pilots/outreach-scripts.md`: первое сообщение в WhatsApp, звонок, визит, напоминания, ответы на
      возражения;
    - `gtm/pilots/demo-script.md`: показ за 10 минут;
    - `gtm/pilots/pilot-agreement.md`: шаблон условий пилота («проверить у юриста»);
    - `gtm/pilots/pilot-scorecard.md`: метрики пилота и критерии успеха.

3.7 **Решения** — записи в `plan/DECISIONS.md` по каждому существенному выбору этого этапа: границы сценария,
    провайдер и модель, канал передачи заявки, цена-гипотеза, методы проверки спроса, источники рыночных цифр.

Бонус, если остаётся лимит: казахская версия предложения (пометка «нужна проверка носителем языка»); в
`mandala/mandala.json` — `ready` для действий, у которых появились заготовки, затем `python3 mandala/build.py`.
