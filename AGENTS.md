# Правила для агентов (и людей)

Прочитай этот файл, затем `STATUS.md` (что уже сделано). Если ты облачный этап — свой промпт в `plan/stages/`.

## Рабочее соглашение

- Всё живёт в этом репозитории: `github.com/yk59m2cmhw-hash/u`, ветка `main`.
- Коммит и push после каждого пункта этапа, чтобы прогресс не терялся, если этап оборвётся по лимиту.
- Перед работой — `git pull`. Перед push из shallow-клона — `git fetch origin main` и `git rebase origin/main`.
  Никогда не делать force-push в `main`.
- Если предыдущий этап оборвался, сначала доделай его незакрытые пункты (они отмечены в `STATUS.md`), потом свои.
- В конце этапа обнови `STATUS.md` и таблицу этапов в `README.md`.

## Репозиторий публичный

- Никаких личных данных: имён, контактов, документов, адресов, страны проживания основателей, переписки,
  данных клиентов.
- Никаких ключей и секретов. Конфиги — через `.env.example`, реальные значения только в переменных окружения.

## Качество

- Каждая цифра про чужие программы, цены и условия — со ссылкой на источник и датой проверки
  (`проверено 2026-11-12`). Официальная страница важнее агрегатора.
- Оценки помечаются как оценки, с допущениями.
- Ничего не выдумывать: нет данных — так и пишем, оставляем `[ЗАПОЛНИТЬ]` (в английских материалах `[FILL IN]`).
- Код — с тестами, которые реально запускались. В отчёте написать, что запускалось и с каким результатом.

## Границы

- Никаких советов по обходу правил программ, KYC или санкций. Одна компания — одна заявка, никаких фиктивных
  компаний и аккаунтов.
- Кредиты не перепродаются и не передаются; «голые» VM клиентам не продаём.
- Данные клиентов не используются для обучения без их письменного согласия.
- Юридические и налоговые материалы — ориентир, а не консультация: помечать «проверить у юриста».

## Язык

- Документы для основателей — на русском.
- Материалы для заявок, сайт и код (комментарии, README модулей) — на английском.

## Мандала

`mandala/mandala.json` — источник; `python3 mandala/build.py` пересобирает `mandala/MANDALA.md` и
`mandala/index.html`. В `ready` — номера действий, для которых в репозитории есть заготовка; в `done` — то,
что основатели реально сделали. Агенты ставят только `ready`.
